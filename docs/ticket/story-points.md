# Story Points

Even if I'm alone on this project, I find value in estimating tickets: not to track velocity or meet sprint deadlines, but to force honest thinking about scope before starting a task.

A few points to highlight:
- There is no deadline, the priority is building a qualitative project, no matter how long it takes.
- With this mindset, there is no need for sprints with a fixed duration (e.g. a 2-week sprint). Sprints here are purely thematic groupings, never timeboxed scope.
- Without sprints, there is no need to track velocity.

Scoring is done in terms of **Estimated Effort** (in days), not complexity or person/days, since there is no fixed sprint duration to plan against.

## Estimation Effort Matrix

| Story Points | Estimated Effort |
|:---|:---|
| 1 | Less than 2 hours |
| 2 | Half a day |
| 3 | Up to 2 days |
| 5 | Up to 4 days |
| 8 | Up to 1 week |

## Important

- If an estimated ticket exceeds 8 Story Points, the ticket needs to be split.
- **Learning a new skill or technology (+1 to +2 points)**: if a ticket requires picking up a technology, library, or concept never used before, factor in the research and experimentation time. The less familiar the territory, the higher the bump.
